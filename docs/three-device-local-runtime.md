# اجرای محلی Holo-Dark روی سه دستگاه

## هدف این مرحله

این راهنما مسیر آزمایشی اجرای برنامه و Express روی هر دستگاه را توضیح می‌دهد؛ بدون اینکه شاخه اصلی یا منطق حسابداری تغییر کند. این مرحله به‌تنهایی به معنی تکمیل و تأیید همگام‌سازی سه‌دستگاهی نیست.

## وضعیت معماری فعلی که باید حفظ شود

- رابط وب با Vite و React ساخته می‌شود.
- سرور Express در `server.ts` فایل‌های ساخته‌شده در `dist` را ارائه می‌کند و APIها را اجرا می‌کند.
- ذخیره‌سازی محلی با Dexie/IndexedDB در مرورگر انجام می‌شود.
- همتاسازی داده‌ها در `src/lib/p2pMeshSync.ts` با PeerJS/WebRTC انجام می‌شود.
- PWA به‌تنهایی Node.js را روی Android اجرا نمی‌کند؛ برای اجرای Express روی Android به محیطی مانند Termux و Node.js نیاز است.

## لپ‌تاپ

1. Node.js نسخه پشتیبانی‌شده و Git را نصب کنید.
2. مخزن خصوصی را با حساب مجاز GitHub دریافت کنید.
3. در پوشه پروژه اجرا کنید:

```sh
npm install
npm run build
npx tsx server.ts
```

4. روی همان لپ‌تاپ، `http://127.0.0.1:3000` را باز کنید.

## هر گوشی Android

1. برنامه Termux را از منبع رسمی آن نصب کنید.
2. در Termux اجرا کنید:

```sh
pkg update
pkg install nodejs-lts git
```

3. مخزن خصوصی را با روش امن احراز هویت GitHub دریافت کنید؛ توکن یا رمز را داخل اسکریپت یا فایل مخزن ننویسید.
4. در پوشه پروژه اجرا کنید:

```sh
npm install
bash scripts/start-local-android.sh
```

5. در مرورگر همان گوشی آدرس `http://127.0.0.1:3000` را باز کنید. سپس در صورت ارائه گزینه نصب، PWA را به صفحه اصلی اضافه کنید.

اسکریپت `scripts/start-local-android.sh` وابستگی‌ها را در صورت نیاز نصب می‌کند، نسخه وب را می‌سازد و سرور Express را با TSX اجرا می‌کند.

## محدودیت‌ها و مواردی که هنوز باید پیاده‌سازی/آزمایش شوند

1. **پایداری پس‌زمینه اندروید:** Android/Termux ممکن است پردازه را در حالت ذخیره باتری متوقف کند. برای استفاده واقعی باید محدودیت باتری، اعلان/سرویس پایدار و راه‌اندازی مجدد پس از خاموش/روشن شدن دستگاه بررسی شود. این اسکریپت سرویس دائمی اندروید ایجاد نمی‌کند.
2. **سیگنال‌دهی PeerJS:** کد فعلی PeerJS از سرور سیگنال‌دهی پیش‌فرض استفاده می‌کند. WebRTC معمولاً داده را مستقیم بین همتاها جابه‌جا می‌کند، اما برای پیدا کردن همتاها همچنان سیگنال‌دهی لازم است. بنابراین در این وضعیت، برنامه کاملاً بدون سرویس بیرونی نیست.
3. **NAT و شبکه موبایل:** STUN به‌تنهایی همه شبکه‌ها را پوشش نمی‌دهد. بعضی اتصال‌ها به TURN نیاز دارند که ممکن است ترافیک را رله کند.
4. **شناسه دستگاه:** شناسه‌های ثابت فعلی برای سه نصب مستقل باید از نظر ثبت هم‌زمان، تعویض دستگاه و بازیابی بررسی شوند. قبل از تغییر شناسه‌ها باید داده‌های موجود حفظ شوند.
5. **امنیت:** سرور فعلی روی `0.0.0.0` گوش می‌دهد. پورت 3000 را بدون احراز هویت و بررسی امنیتی روی اینترنت عمومی باز نکنید. از فایل `.env` محلی استفاده کنید و کلیدهای محرمانه را در Git قرار ندهید.
6. **همگام‌سازی حسابداری:** قبل از استفاده عملیاتی باید تست هم‌زمانی سه دستگاه، قطع و وصل اینترنت، ارسال دوباره عملیات، تعارض و جلوگیری از ثبت تکراری اسناد اجرا شود.

## معیار پذیرش پیش از انتشار

- هر دستگاه به‌تنهایی برنامه و API محلی را اجرا کند.
- `GET /api/health` روی هر دستگاه پاسخ سالم بدهد.
- داده محلی بعد از بستن و باز کردن برنامه باقی بماند.
- هر سه دستگاه با شناسه مستقل در شبکه ظاهر شوند.
- تغییرات فقط یک‌بار منتقل شوند و پس از قطع/وصل اینترنت بازیابی شوند.
- هیچ راز یا کلید سرویس در بسته وب یا مخزن عمومی قرار نگیرد.

این راهنما مرحله آماده‌سازی اجرای محلی است، نه تأیید نهایی سه‌دستگاهی. تا زمانی که تست‌های بالا روی لپ‌تاپ و هر دو گوشی اجرا نشده‌اند، از آن برای ثبت اسناد واقعی حسابداری استفاده نکنید.
